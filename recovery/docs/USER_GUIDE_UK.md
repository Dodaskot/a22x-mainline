# A22x Linux Recovery 0.5 — користування

Цей recovery призначений для Samsung Galaxy A22 5G **SM-A226B / MT6833** з
підготовленим ядром #107. Він запускається з окремого розділу RECOVERY та працює
в оперативній пам’яті. Версію, яка справді встановлена на телефоні, треба
звіряти з результатом прошивання й холодного запуску; наявність цього документа
сама по собі не підтверджує встановлення.

## Екран і кнопка Power

Коротке натискання бічної кнопки Power гасить підсвітку. Наступне натискання
повертає попередній рівень яскравості. Дотики до погашеного екрана та палець,
утриманий на екрані під час пробудження, не повинні запускати кнопки.

Відкрийте **Tools and diagnostics → Display**. Повзунок змінює яскравість від
1 до 100%; значення застосовується після відпускання пальця. Там само є
перемикання 60/90 Hz. Обрані значення діють у поточному сеансі recovery.
Погашення підсвітки не зупиняє копіювання або резервне копіювання.

90 Hz — частота панелі. Фактична плавність залежить також від часу малювання
інтерфейсу та операцій із файлами; це не обіцянка постійних 90 кадрів за секунду.

## Провідник і текстові файли

Відкрийте **Files**, оберіть том і явно змонтуйте його для читання або для
читання й запису. Linux розміщений у `userdata`; після монтування його корінь
доступний за адресою `/mnt/volumes/userdata`. Зовнішня SD, підключена через
Storage, доступна за адресою `/mnt/backup`.

Свайп прокручує початковий список томів, вміст папки, перегляд тексту та редактор
за пікселями. Після відпускання діє інерція. Дотик під час інерції спочатку
зупиняє рух, тому випадкова зупинка пальцем не має відкрити файл.

Типи записів відрізняються кольором, іконкою та текстовою позначкою. Доступні
створення, копіювання, перейменування, редагування тексту, зміна прав і власника,
видалення файлів та порожніх каталогів. Збереження редагованого файлу перевіряє,
чи не змінив його хтось інший. Символьні посилання відкриваються через окрему
перевірену дію; довільного рекурсивного видалення тут немає.

## Доступ із ПК

У розділі USB file sharing оберіть вже змонтований `userdata` або SD та режим
**Read only** чи **Read/write**. Натисніть Start, працюйте з файлами у провіднику
ПК, закрийте передачі й натисніть Stop. Сервіс не запускається автоматично.

MTP призначений для звичайних файлів. Для системних файлів із важливими UID/GID,
ACL, capabilities, посиланнями або спеціальними типами використовуйте SFTP/SSH
чи штатний Linux-бекап. Редактор на ПК може зберегти файл через заміну inode;
це може змінити метадані навіть тоді, коли текст виглядає правильним.

SSH і SFTP працюють через USB за адресою `172.16.42.1`, з уже дозволеним ключем
цього ПК. Відбиток SSH-сервера змінюється після нового запуску recovery, бо
ключ створюється в RAM. Звіряйте його з Diagnostics перед оновленням довіри.
Закрийте MTP, термінал і SSH-сеанси перед Backup, Wipe, Restore або встановленням.

## Термінал

Відкрийте **Tools and diagnostics → Terminal → Start local shell**. Команди
працюють від root у RAM-середовищі recovery. Для файлів встановленої ОС
використовуйте її шлях у `/mnt/volumes/userdata`; для SD — `/mnt/backup`.

Є EN/UK, Ctrl+C, Ctrl+D, Tab, Escape, стрілки та прокрутка виводу. Це базовий
VT100-сумісний екран: підтримка складних повноекранних програм обмежена.
Вивід зберігається лише в обмеженому RAM-буфері, історія команд не записується
на диск. Завершуйте роботу через **Close terminal → Close session and return**,
щоб звільнити доступ для інших операцій recovery.

## Повний тест Linux: Backup → Verify → Wipe → Restore

Linux-профіль зберігає **BOOT та зайняті блоки ext4 userdata** зі стисненням.
Вільна частина userdata не копіюється. Це повний набір для відновлення
поточного Linux у підтримуваній схемі; інші розділи прошивки не входять до нього.
Розмір залежить від зайнятих блоків та стисливості даних, а не від повної
місткості userdata.

1. Залиште зовнішню ext4 SD у телефоні. У **Storage** оберіть її як місце
   резервних копій. Перевірте вільне місце, яке показує план.
2. Закрийте MTP, Terminal та SSH. Відкрийте **Backup**, оберіть Linux-профіль і
   погодьте штатне відмонтування userdata. Подивіться розрахований обсяг та
   виконайте копіювання.
3. Відкрийте **Verify**, оберіть щойно створений завершений snapshot і дочекайтеся
   успішної повної перевірки.
4. Для навмисного тесту очищення відкрийте цей snapshot у **Restore** та дію
   Wipe userdata. Перегляньте план і підтвердьте утриманням кнопки. Ця дія
   форматує userdata; копія на зовнішній SD, BOOT і RECOVERY зберігаються.
5. Виберіть той самий snapshot та Restore. Recovery відновлює userdata,
   перевіряє запис і обробляє BOOT останнім. Уже ідентичний BOOT пропускається.
6. Після успішного завершення відкрийте **Power → Linux**.

Для цього тесту робіть **свіжий бекап у тому самому сеансі recovery**.
Звичайний запуск Linux або зміна userdata роблять старий snapshot неактуальним
для перевірки перед Wipe. Не видаляйте резервну копію з ПК, поки не перевірите
запуск і дані відновленої системи.

Попередня кваліфікація відновлює справжній бекап телефона у нові образи-файли
на ПК та перевіряє файлову систему, дані й метадані. Це не дорівнює вже
виконаному фізичному Wipe/Restore телефона. Такий тест виконується тільки після
окремого навмисного вибору цих дій.

## Інші ARM64-дистрибутиви

У **Tools → Linux Systems** імпортується підготовлений ARM64 rootfs-пакет із
`bundle.json`. Кожна система має власні системні каталоги, пакети, `/etc` та
`/var`. Домашній каталог `/home` спільний. Перемикання зберігає попередню систему
в окремому слоті; загальне ядро #107, модулі та прошивки мають відповідати
профілю цього телефона.

ISO Debian AArch64 та Fedora RAW спочатку треба дослідити й перетворити на
сумісний пакет. Recovery не записує довільний образ диска поверх пам’яті
телефона. AArch64 визначає архітектуру процесора, але не забезпечує сумісність
завантаження, дисплея, модема, графіки, аудіо або енергозбереження.

Спільний `/home` не робить налаштування всіх дистрибутивів взаємозамінними:
потрібні сумісні UID/GID, а нові версії програм можуть змінювати формати своїх
налаштувань. Незавершене перемикання видно в Systems; явно оберіть Resume або
Rollback перед звичайним завантаженням.

## BOOT та повернення на сток Android

Відкрийте **Tools → Install images**. Для BOOT потрібен правильний A22x boot
image на зовнішній SD. Для стоку потрібен manifest підготовленого комплекту
прошивки. В обох випадках явно оберіть перевірений Linux snapshot, перегляньте
список записуваних і пропущених розділів та підтвердьте план утриманням:
три секунди для BOOT, п’ять для стоку.

Стоковий комплект замінює потрібні розділи Android, а **RECOVERY записує
останнім**, тож після завершення custom recovery буде замінено стоковим.
userdata інсталятор не форматує. Для запуску Android із колишнім Linux userdata
потрібен навмисний factory reset у stock Recovery — він зітре Linux-дані.
Для повернення до Linux знову встановіть custom recovery та відновіть
збережений BOOT/userdata snapshot.

Підтримка встановлення Android не означає підтримку монтування, дешифрування,
бекапу або відновлення Android. Захищені завантажувачі й модем цим
інсталятором не записуються. Після перерваного встановлення потрібен явно
переглянутий Resume-план; автоматичного продовження чи перезавантаження немає.
